# Methodology — канонічні джерела (єдине джерело істини)

Ця тека містить повний довідник методу. Щоб уникнути дрейфу правил (одне правило, переказане в
багатьох файлах, що тихо розходяться), кожне наскрізне правило має **один канонічний дім**.
Усюди в інших місцях слід **посилатися** на цей файл, а не копіювати його текст.

## Канонічні доми
| Правило / артефакт | Канонічний дім |
|--------------------|----------------|
| Шкала довіри L0–L5 + правило промоції / рішення | `methodology/trust-levels.md` |
| Version gate (флагманське правило) | `methodology/version-discipline.md` |
| Цикл валідації (question→…→decision) | `methodology/validation-cycle.md` |
| Механіка ради, склад агентів + тригер промоції до Agent-Team | `methodology/board-roles.md` |
| MCP-розширення (user-level; multi-model L1 + зовнішній тестер) | `methodology/board-roles.md` |
| Ієрархія типів джерел + правило різноманіття | `.claude/skills/source-trust/SKILL.md` |
| Розподіл reporter-готує / orchestrator-зберігає, структура звіту, мова виводу | `CLAUDE.md` §6 |
| Рівні глибини валідації (Fast / Standard / Deep) | `CLAUDE.md` §2 (повний розбір — у файлі циклу) |

## Один навмисний виняток: промпти сабагентів
Файли в `.claude/agents/` **навмисно повторюють** правила, які вони забезпечують. Сабагент працює
в ізольованому контексті й **не бачить `CLAUDE.md` чи цю теку** — тож правило, якому він має
підкорятися, мусить жити в його власному промпті. Це дублювання обов'язкове, не випадкове; не «дедуплікуй» його.

Усюди, що *поділяє* контекст оркестратора (`CLAUDE.md`, `INFO.md`, `README.md`, скіли), слід
посилатися на канонічний дім, а не переписувати його.
