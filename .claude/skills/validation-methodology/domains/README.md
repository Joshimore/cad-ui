# Доменні паки (`domains/`)

Ядро системи доменно-нейтральне (метод, шкала довіри L0–L5, агенти, шаблони). Специфіка
конкретної області живе у **паку** тут — щоб спільне ядро не розпухало, а проєкт лишався переносним.

**Ядро не постачає жодного пака** — є лише контракт `_TEMPLATE/`. Кожен учасник команди додає
власний пак під свою спеціалізацію.

## Як додати свій пак
Повний контракт — у `_TEMPLATE/README.md`. Стисло:
1. Скопіюй теку `_TEMPLATE/` і перейменуй у **kebab-case** (напр. `my-domain`, `web-backend`).
2. Заповни `pack.md` — `pack_name`, `description`, `test_execution` (`human` / `auto`), `version_pins`.
3. Заповни `sources.md` (довірені джерела + version pins) і `knowledge.md` (довідник домену).
4. Опційні пак-специфічні агенти — у теці `agents/` цього пака.

## Як ядро використовує пак
На задачі оркестратор перевіряє `domains/` на релевантний пак; якщо він підходить — підвантажує
його `knowledge.md` і `sources.md` та читає режим `test_execution` з `pack.md`. **Паки опційні:**
якщо потрібного пака немає або він неповний — система просто відкочується (fallback) до ядра, не блокуючись.

## Version Gate
`version_pins` у паку — не формальність: відповідність версії ПЗ — головне правило системи
(див. `../methodology/version-discipline.md`). Пак без запінених версій тягне довіру вниз.
