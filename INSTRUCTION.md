# INSTRUCTION — настройка среды после клонирования

Пошаговая инструкция для нового члена команды: что сделать на своём компьютере,
чтобы CAD UI и весь рабочий процесс заработали правильно.

> **Совет:** не делай всё вручную. Пройди Шаги 0–2 (запуск), а дальше нажми
> **«>_ Claude»** вверху справа и напиши в терминале: *«прочитай INSTRUCTION.md и
> помоги настроить среду»* — Claude выполнит проверку и настройку вместе с тобой.

---

## Шаг 0. Что должно стоять на компьютере

Проверь в терминале (PowerShell / cmd), что установлено:

| Программа | Проверка | Если нет |
|---|---|---|
| **Python 3.11+ с pip** | `python --version` и `python -m pip --version` | [python.org](https://www.python.org/downloads/) — при установке отметь галочку **Add Python to PATH** |
| **Git** | `git --version` | [git-scm.com](https://git-scm.com/downloads) |
| **Claude Code** *(для кнопки `>_ Claude`)* | `claude --version` | установи Claude Code (иначе кнопка запуска не сработает) |
| **Node.js / npx** *(только для брендированных `.docx`/`.pptx`)* | `npx --version` | [nodejs.org](https://nodejs.org/) — нужен лишь если будешь делать Word/PowerPoint; PDF/Excel работают без него |

> ⚠️ **Частая ловушка (Windows):** бывает, что в PATH лежит Python без pip (например,
> сборка MSYS/Git-for-Windows). Если `python -m pip --version` ругается — поставь
> обычный Python с python.org. `start.bat` создаёт своё окружение `.venv` и им же
> ставит зависимости, так что после установки нормального Python всё поднимется само.

## Шаг 1. Склонируй репозиторий

```
git clone https://github.com/Joshimore/cad-ui.git
cd cad-ui
```

---

## Шаг 2. Запусти `start.bat`

Просто дважды кликни по `start.bat` в папке `cad-ui` (или запусти из терминала).
При **первом** запуске скрипт сам:

1. создаст виртуальное окружение `.venv`;
2. установит зависимости из `requirements.txt`;
3. поднимет локальный сервер и откроет браузер на **http://127.0.0.1:8145**.

Окно терминала, которое открылось, — это и есть сервер. Закроешь его — UI остановится.

> **Linux / macOS или запуск вручную:**
> ```
> python -m venv .venv
> .venv/bin/pip install -r requirements.txt      # Windows: .venv\Scripts\pip ...
> .venv/bin/python run_ui.py                      # Windows: .venv\Scripts\python ...
> ```
> Опции: `--port 9000`, `--no-browser`. Можно указать другую рабочую папку:
> `python run_ui.py D:\my-workspace` (по умолчанию — сама папка cad-ui).

**Проверь, что работает:** в браузере открылся «Центр управления», слева навигация,
внизу зелёная строка `локально · 127.0.0.1`. Готово — среда запущена.

## Шаг 3. Настрой среду через Claude (рекомендуется)

1. Нажми кнопку **«>_ Claude»** вверху справа — откроется терминал с Claude Code
   прямо в корне рабочей папки.
2. Напиши ему: **«прочитай INSTRUCTION.md и CLAUDE.md и помоги настроить среду»**.
3. Claude автоматически читает `CLAUDE.md` при старте, так что уже понимает систему.
   Он поможет:
   - проверить, что зависимости и окружение в порядке;
   - объяснить структуру папок и разделы интерфейса;
   - при необходимости — создать агентов/навыки Claude Code под твою область работы
     (по файловым контрактам из `CLAUDE.md`);
   - настроить персональный конфиг (Шаг 4).

Если кнопка `>_ Claude` пишет, что команда не найдена — установи Claude Code (Шаг 0)
или укажи свою команду запуска в `workspace.config.json` → `claude_command` (Шаг 4).

---

## Шаг 4 (опционально). Персональный конфиг

Без конфига всё работает на дефолтах. Если нужно исключить свои личные папки из
сканирования или задать нестандартную команду запуска Claude:

1. Скопируй `config.example.json` в **корень папки cad-ui** под именем
   **`workspace.config.json`**.
2. Впиши свои значения:
   ```json
   {
     "exclude_dirs": ["моя-личная-папка", "*_cache"],
     "exclude_extensions": [".parquet"],
     "claude_command": "claude"
   }
   ```
3. Перезапусти `start.bat`, чтобы конфиг применился.

> Файл `workspace.config.json` **в git не попадает** (он в `.gitignore`) — у каждого
> он свой. `claude_command` из конфига применяется только когда рабочая папка = сам
> репозиторий cad-ui (изолированный режим) — это защита: конфиг из чужой открытой
> папки не сможет запустить у тебя произвольную команду.

## Шаг 5 (опционально). Discord-статусы

Навык `/status` (русские статусы дня, «Трек» по задачам, PDF-отчёты в каналы проектов)
уже в комплекте — нужно только настроить свои Discord-вебхуки. Проще всего: запусти
`>_ Claude` и скажи **«настрой status по SETUP.md»** — Claude проведёт по шагам. Или
открой **`.claude/skills/status/SETUP.md`** и настрой вручную.

> Вебхуки — секреты; они живут только в `workspace.config.json` (в блоке `status`), а он
> в `.gitignore`. В общий репозиторий не попадают.

## Что коммитится, а что остаётся у тебя локально (важно!)

Чтобы не закоммитить своё личное и не ждать чужого, запомни git-модель:

| Едет в общий репозиторий (коммитится) | Остаётся только у тебя (в `.gitignore`) |
|---|---|
| код (`app/`, `run_ui.py`, `*.bat`) | твоё окружение `.venv/` |
| агенты и навыки `.claude/agents/`, `.claude/skills/` (**это и есть система**) | состояние UI `.cad-ui/` (избранное, поисковый индекс) |
| документация: `README.md`, `INSTRUCTION.md`, `CLAUDE.md` | **содержимое** `Working directory/` — твои проекты и задачи |
| пустые «скелеты» папок (только их `.gitkeep`) | **содержимое** `knowledge-base/` — твои карточки знаний |
| | твой `workspace.config.json` |

**Смысл:** папки `Working directory/` и `knowledge-base/` приезжают пустыми (только
`.gitkeep`), а их содержимое у каждого своё и в общий репозиторий не попадает. Агенты
и навыки — общие, они и есть общий инструмент команды.

## Разделы интерфейса (куда смотреть)

- **Центр управления** — состояние пространства: счётчики, недавние изменения, таймлайн дедлайнов.
- **Документы** — дерево файлов + markdown-вьюер; открытый `.md`/текст можно править прямо во вьюере (кнопка «✎ Редактировать»).
- **Поиск** — полнотекстовый (SQLite FTS5), автотеги, фильтры.
- **Недавние / Избранное** — последние изменённые и закреплённые (★) файлы.
- **Проекты** — проекты и задачи в `Working directory/`: дедлайны, статусы, цвета.
- **Граф** — граф связей: документы, агенты, навыки; рёбра по ссылкам и `[[wiki]]`.
- **База знаний** — карточки с уровнем доверия L0–L5 и версией ПО (появляется, когда есть хотя бы одна карточка).
- **Реестр: Агенты / Навыки** — появляется автоматически, когда в `.claude/` есть агенты/навыки.
- **Тема** (☾/☀ вверху справа) — светлая/тёмная, запоминается.

## Обновление системы позже

Когда в общем репозитории появятся обновления:

```
update.bat
```
(делает `git pull` + досинхронивает зависимости). После этого перезапусти `start.bat`.

> Твои локальные данные (`Working directory/`, `knowledge-base/`, `.cad-ui/`,
> `workspace.config.json`) обновление не трогает — они не в git.

## Если что-то не работает

- **Браузер не открылся / «сайт недоступен»** — проверь окно терминала от `start.bat`
  на ошибки; открой вручную http://127.0.0.1:8145.
- **`ERROR: could not create venv` / pip не найден** — Python в PATH без pip; поставь
  обычный Python 3.11+ с python.org (см. ловушку в Шаге 0).
- **Порт 8145 занят** — запусти на другом порту: `.venv\Scripts\python run_ui.py --port 9000`.
- **Кнопка `>_ Claude` — «команда не найдена»** — установи Claude Code или пропиши
  `claude_command` в `workspace.config.json`.
- **Изменил `.py`, а поведение прежнее** — сервер без авто-перезагрузки: закрой окно
  сервера и запусти `start.bat` заново (правки CSS/JS подхватываются простым обновлением
  страницы).
